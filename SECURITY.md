# Security reporting

This is an experimental, unauthenticated local service. Keep it on localhost and
use dedicated, access-controlled workspaces. Only the current Public V0 source
candidate is in scope; there is no security response-time or production support
commitment.

Do not put real photos, person_engine databases, registry files, embeddings,
snapshots containing real identity facts, secrets or tokens in public issues.
Use generated anonymous fixtures and a minimal sanitized description for ordinary
bug reports. Check logs, filenames, paths and attachments before sharing them.

GitHub Private Vulnerability Reporting: **TO_ENABLE_AFTER_REPOSITORY_CREATION**.
The repository owner should enable it after creating the GitHub repository.
Until a private reporting channel is available, do not publish exploit details
or sensitive artifacts in an issue. No private email address is required here.

See the [privacy notice](docs/privacy.md) for workspace and snapshot boundaries.
